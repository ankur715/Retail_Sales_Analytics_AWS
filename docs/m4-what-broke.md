# Milestone 4: what broke and why

| # | What broke | Why | Fix |
|---|---|---|---|
| 1 | The chatbot crash-looped in kind: `No module named 'jwt'`, though every test passed on the laptop | PyJWT was never in `requirements.txt`. It was installed locally only because another package pulled it in. CI's unit-test job failed for the same reason. | Added `PyJWT[crypto]` to `requirements.txt`. Lesson: a clean install (CI, a fresh image) is the real dependency test. |
| 2 | The migration-safety CI job failed with `No module named 'requests'` | `etl.config` started importing the new secrets reader, which imported `requests` at the top. That job installs only two small packages. | Import `requests` only when Vault is actually configured, so `etl.config` stays importable everywhere. |
| 3 | Redpanda crash-looped after hardening: "advertised_rpc_api ... improperly configured" | With a read-only root filesystem, `/etc/redpanda` became an empty writable folder, which hid the image's default config, the thing that set the RPC address | Pass `--rpc-addr` and `--advertise-rpc-addr` explicitly |
| 4 | The access demo marked Cobalt's own query and the admin's all-brands query as wrong | Not an access bug: "last week" is the latest loaded week, and only one retailer had reported it, with Aurora sales only. Cobalt really had 0 rows and the admin really saw 1 brand. | The demo asks about the last 4 weeks, where all three brands have data, so "confined" and "empty" look different |
| 5 | The generated credentials file was world-readable (`rw-rw-rw-`) despite `umask 077` | The Codespace workspace folder has default ACLs that override umask | `chmod 600` explicitly after writing it (the folder is also gitignored) |
| 6 | `deploy/auth/up.sh` printed "required variable ... is missing" after a successful start | The final `docker compose ps` didn't get `--env-file`, so Compose couldn't resolve the `${VAR:?}` guards | Pass the env file to every compose call |
| 7 | Trivy's first run failed on three files and an image | (a) `.devcontainer/Dockerfile` had no `USER`. (b) The Redshift security group allows all egress. (c) S3 uses SSE-S3, not a KMS key. (d) The image had old `wheel` (CVE-2026-24049) and setuptools' vendored `jaraco.context` (CVE-2026-23949). | (a) `USER vscode`. (d) Upgrade pip/setuptools/wheel in the image (verified with Trivy in the Codespace before pushing). (b) and (c) accepted in `.trivyignore` with reasons and a 2027-01-31 expiry: fixing (b) is a live AWS change for the owner to approve. |
| 8 | Without the fix, one brand could have been served another brand's cached answer | Milestone 2's cache key was the question and data version only. Once answers depend on who asks, "same question" isn't "same answer". | Cache, stale-fallback and idempotency keys include the caller's brand scope or subject; tested both ways |
| 9 | The first GitHub checks screenshot showed one collapsed "CI" row, not the scans | The PR checks page groups jobs under the workflow, and its expand control isn't a stable selector | Screenshot the workflow run page, which lists every job |
